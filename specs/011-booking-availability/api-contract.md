## 2. DTO shapes (draft)

### AvailabilityRulesResponse
- `bufferMinutes: number` — effective buffer (schema default or resource override)
- `rules: AvailabilityRuleDto[]` — resource-specific rules (or schema rules for schema-level GET)
- `inheritedRules: AvailabilityRuleDto[] | null` — schema rules when endpoint is resource-level; `null` for schema-level GET

### AvailabilityRuleDto
- `ruleId: string` (GUID)
- `ruleType: "RECURRING" | "ONE_OFF"`
- `ruleMode: "AVAILABLE" | "UNAVAILABLE"`
- `daysOfWeek: number[] | null` — DayOfWeek values (0=Sunday … 6=Saturday); populated for RECURRING, `null` for ONE_OFF
- `startTime: string` — wall-clock time in `HH:mm` format
- `endTime: string` — wall-clock time in `HH:mm` format
- `endDayOffset: number` — `0` (same day) or `1` (next calendar day, auto-set when endTime < startTime)
- `startDate: string | null` — ISO 8601 date (`YYYY-MM-DD`); populated for ONE_OFF, `null` for RECURRING
- `endDate: string | null` — ISO 8601 date (`YYYY-MM-DD`); populated for ONE_OFF, `null` for RECURRING

### RuleSetUpdateRequest
- `bufferMinutes: number` — required; 0 = no buffer
- `rules: NewRuleRequest[]` — full replacement set; empty array = clear all rules

### NewRuleRequest
- `ruleType: "RECURRING" | "ONE_OFF"` — required
- `ruleMode: "AVAILABLE" | "UNAVAILABLE"` — required
- `daysOfWeek: number[] | null` — required for RECURRING; must be omitted or `null` for ONE_OFF
- `startTime: string` — required; `HH:mm` format
- `endTime: string` — required; `HH:mm` format
- `startDate: string | null` — required for ONE_OFF (`YYYY-MM-DD`); must be omitted or `null` for RECURRING
- `endDate: string | null` — required for ONE_OFF (`YYYY-MM-DD`); must be omitted or `null` for RECURRING

### Error responses (shared across all 4 endpoints)

**400 Bad Request** (validation errors):
- `{ "code": "validation_error", "detail": "..." }` — AVAIL×AVAIL overlap, past date, invalid timezone, malformed time/date, etc.

**401 Unauthorized** — missing or expired JWT

**403 Forbidden** — caller is not the group owner

**404 Not Found** — schema or resource not found in Availability read-models (i.e., the entity was never created or its event was not yet processed)

## 4. Resolved questions

- Q: `bufferMinutes` upper bound — what is the maximum allowed value? | A: max 1440 (24 hours); simple guard against obvious abuse without being restrictive
- Q: Resource-level GET — when a resource has no rule set yet (no PUT has been called), should the response return 200 with empty `rules` array and inherited schema rules, or 404? | A: 200 with empty `rules: []` and inherited schema rules (never 404 — an empty rule set is valid state)
- Q: Schema-level GET — when a schema has no rule set yet, should the response return 200 with empty rules or 404? | A: 200 with empty `rules: []` and `inheritedRules: null` (never 404)
- Q: `AvailabilityRulesResponse.bufferMinutes` for resource-level GET — should it return the effective value (resource override if present, else schema default) or two separate fields (`bufferMinutes` + `schemaBufferMinutes`)? | A: single `bufferMinutes` field returns the effective value (resource override if not null, else schema default); simpler for the FE
- Q: `daysOfWeek` encoding — 0=Sunday or 0=Monday? | A: 0=Sunday … 6=Saturday (matches .NET DayOfWeek enum); FE can re-map to ISO if needed

## 5. Notes

- Scope confirmed as `both` from `spec.md` (`**Scope**: both`).
- `AvailabilityCalendarPreviewComponent` consumes no additional API endpoints — it receives data as `@Input()` from the parent tab components; no separate calendar endpoint is needed in this iteration.
- The `bufferMinutes` field on the resource-level `RuleSetUpdateRequest` may be `null` or `0` to distinguish "inherit from schema" vs. "explicitly 0". The plan specifies `null` = inherit; this needs confirmation in contract-definer finalization.
- `inheritedRules` field is `null` (not an empty array) for schema-level GETs, so the FE can distinguish "this is a schema endpoint" from "this is a resource endpoint with no schema rules".
- All times are wall-clock in the group's IANA timezone (context label "All times in {TZ}" is rendered FE-side from the group's timezone; no timezone field appears in the availability API response itself).
