# Recenzja projektu workflow (Fable, 2026-09-21) — zapis skrócony

Recenzent zewnętrzny (subagent Fable), bez dostępu do repo; oceniał oryginalny pomysł właściciela i 15-punktową propozycję głównego asystenta. Zapisane 2026-09-28 z kontekstu sesji projektowej; skrót wierny, kolejność zachowana.

## Werdykt
Kierunek dobry (pliki zamiast streszczeń, skrypt zamiast prozy, kontrakt przed BE∥FE, klasyfikacja pytań), ale ~60 % wad audytu naprawionych deklaratywnie. Potok niewykonalny jako jeden skrypt (workflow nie pyta człowieka, nie ma FS). Arbiter jako triage wszystkich uwag i hejter w pętli ze Scrumem powielają wady audytu.

## Najpoważniejsze zastrzeżenia
- **Z1 izolacja to deklaracja** → ACL na ścieżki (`fleet-acl.json` + hook PreToolUse po `agent_type`), brak powłoki u ślepych, worktree z commita bazowego dla testera, `omitClaudeMd` + `skills:`; testy niezależne muszą być czarnoskrzynkowe (HTTP / DOM + mocki z kontraktu); pułapka Windows: kanonizacja ścieżek.
- **Z2 writerzy dalej nie zapytają; koszyk (b) = nowy grób założeń** → zamknięta lista klas decyzji właściciela (kody statusów, authz, kształt odpowiedzi, UI, utrata danych); wykrywanie niezależne od writera (diff swaggera, macierz endpoint×authz, typ `UNSPECIFIED_BEHAVIOR` u reviewera); status `BLOCKED_ON_DECISION`; proweniencja decyzji hookiem; lista (b) wymaga jawnego „ok".
- **Z3 potok niewykonalny jako jeden skrypt** → fazy = osobne workflow, cienki dyrygent w sesji głównej, eskalacje zbiorczo na granicy fazy, wyniki przez `schema`, agenci RO bez Write.
- **Z4 kontrakt prozą = wada 5 w nowym przebraniu** → OpenAPI jako jedyne źródło; część istniejąca generowana z aplikacji; LLM pisze tylko deltę; testy konformancji i mocki z tego samego pliku; test dymny na końcu; rejestr faktów z dowodem.
- **Z5 „aktualizacja spec po naprawach" nie zadziała** → delta spec PRZED poprawką (spec → testy → kod); stan wyliczany, nie deklarowany; checkboxy skryptem.
- **Z6 arbiter jako triage to zła rola** → uwaga musi mieć `rule_ref` + dowód, bez tego jest opinią; domyślna reakcja implementera = naprawa; arbiter tylko spory (UPHOLD/OVERTURN/ESCALATE; zmiana zachowania = zawsze ESCALATE); od rundy 2 uwagi spoza diffu → dług; blockery muszą maleć; po limicie paczka eskalacyjna (kontynuuj / przyjmij z długiem / porzuć).
- **Z7 skala 20–50 stories** → żywa mapa możliwości per moduł (nie stare spec), story przechowuje wersję mapy, pole `supersedes` dla starych AC, `depends_on`.
- **Z8 brak pomiaru** → metryki per story (przerwania, zakopane decyzje, rozjazdy doc–kod, pokrycie AC, defekty po 7 dniach, tokeny/czas, rundy), dziennik z hooków, test dymny floty, audyt jako zestaw regresyjny.

## Niezgody z propozycją (wybór)
- (1) wniosek OK, mechanizm zły: `AskUserQuestion` usuwane subagentom; lepiej `claude --agent`; potrzebne 3 sesje (biznes / discovery / dostawa), bo analityk po 10 rundach jest najgorszym orchestratorem.
- (2) orchestrator-LLM i tak dopisze komentarz → prompty z szablonów w kodzie; hash zużytego wejścia w wyjściu.
- (3) `taskstoissues` = powódź issues; taski w `tasks.md`, issue story z checklistą.
- (6) hejter dostaje propozycję + raport możliwości, nie rozmowę; raport idzie do właściciela niefiltrowany; jedna runda + jedna replika; inny model/effort.
- (9) implementer powinien widzieć testy akceptacyjne (wykonywalna spec), ACL blokuje edycję; spór o test = DISPUTE do arbitra.
- (11) każda konwencja z tagiem `enforced-by: analyzer | archtest | lint | llm-review`; reviewer LLM dostaje tylko `llm-review`.
- (14) tor dobiera kryterium (authz/schemat/kontrakt = pełny); brakuje toru średniego.
- SpecKit: `specify` i `implement` niepotrzebne; `clarify`/`analyze` jako lint; AC ze stabilnymi id.

## Niezauważone luki
Konflikty na plikach współdzielonych przy BE∥FE (krok szeregowy); migracje EF w pętli napraw (jedna migracja na story, regenerowana; utrata danych = ESCALATE); baza testowa per worktree; regresje między stories (pełna suita w DoD); uprawnienia (deny `git push/commit/reset`, `ef database update`; sekrety; GitHub tylko skryptem; brak `bypassPermissions`); awarie infrastruktury (`agent()` → null, limit współbieżności); brak źródła projektu UI; brak modelu uwagi właściciela (skrzynka decyzji, budżet przerwań); `memory:` subagenta jako przeciek między story.

## Docelowa architektura (skrót)
Sesja A `--agent scrum` (capability-analyst, krytyk pomysłu; backlog-writer skrypt) → G1. Sesja B `--agent dev-analyst` (researcherzy; max 3 rundy, budżet pytań; brief, decisions, assumptions, facts, szkic UI; RETURN/SPLIT/TOO_BIG). Sesja C dyrygent + fazy C1 spec/kontrakt/guard planu → G2; C2 tester ślepy (worktree z bazy, bez powłoki) + macierz ról → runner: czerwone; C3 scaffold, writerzy BE∥FE, migracja skryptem + reviewer migracji; C4 runner; C5 reviewerzy ∥ (spec+UNSPECIFIED, konwencje `llm-review`, bezpieczeństwo, design) → dedup → writer | DISPUTE → arbiter; C6 dryf kontraktu, macierz śladu + audytor, regresja, guard kodu, doc-writer (mapa możliwości), status GitHub, metryki → G3. Skrypty bez LLM: runner, dryf, dedup, macierz, status, checkboxy, GitHub, dziennik, ACL, test dymny.
