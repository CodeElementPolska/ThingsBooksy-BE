# Implementation Plan: Rename resource type to resource schema

**Branch**: `016-rename-resource-schema` | **Date**: 2026-10-02 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/016-rename-resource-schema/spec.md`; story `runs/016-rename-resource-schema/story.md`; facts F-0..F-7, decisions DEC-1..DEC-5, assumptions ASM-1..ASM-18 in `runs/016-rename-resource-schema/discovery/`; contract `runs/016-rename-resource-schema/contract-next.json`.

## Summary

One word everywhere: "resource type" becomes "resource schema" in the Resources API (addresses, field, model and operation names, messages, one error code), the backend code, the database object names and the frontend, with no change of behaviour or access rules. Technical approach (DEC-5): **two steps in one story**.

1. **Step 0 - internal rename, behaviour-neutral, before the delivery baseline.** C# identifiers in production and test code change; database names are pinned to today's and nothing a client can observe changes. Proven by the unchanged existing test suite, an identical exported API description and no pending model change.
2. **Visible change through the standard delivery phases.** Skeleton = remove the database pins; developer-only migration made of rename operations (DEC-1) + migration-check + G2b; blind acceptance tests against the new contract; behaviour = addresses, JSON names, operation names, messages, error code; then the frontend.

## Technical Context

**Language/Version**: C# 13 / .NET 10 (backend); TypeScript / Angular 21 (frontend)  
**Primary Dependencies**: ASP.NET Core 10 Minimal API, EF Core 10 (Npgsql), Swashbuckle; Angular standalone + signals, `swagger-typescript-api` ^13.9.1 (generated files in `frontend/src/app/api/`, no npm script - ASM-9)  
**Storage**: PostgreSQL 17, schema `resources` (EF default constraint names, PascalCase columns, explicit `ToTable` - F-4)  
**Testing**: xUnit integration tests on Testcontainers + Respawn (`ThingsBooksyWebAppFactory`, `MigrateAsync` for every DbContext - F-4); Vitest via `ng test` (frontend)  
**Target Platform**: single deployable (backend + frontend), Docker; development database = named volume `postgres_data` (ASM-10)  
**Project Type**: web application - modular monolith backend + Angular frontend  
**Performance Goals**: none (rename only)  
**Constraints**: no behaviour change; no alias for old addresses; one migration for the module in this story (constitution VI); migration is developer-only; rename operations only (DEC-1); lifecycle event contracts and `PropertyDataType` untouched  
**Scale/Scope**: ~80 backend files / 681 occurrences (F-1), 2 ManagementGroups test files, 12 frontend files / 60 occurrences (F-0, F-3); 10 endpoints, 5 of them re-addressed; 1 table, 2 columns, 1 PK, 1 FK, 2 indexes renamed
