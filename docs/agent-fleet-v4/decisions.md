## Ustalenia wynikające z recenzji (przyjęte bez osobnego pytania)

- Trzy sesje: **biznes → discovery → dostawa**; każda startuje z czystego kontekstu i czyta wyłącznie pliki.
- Subagent i skrypt workflow **nie mogą** zapytać człowieka → bramki właściciela są granicami faz (docelowo 3 na story + wyjątkowa przy migracji destrukcyjnej).
- Ramy = mechanizmy (allowlista narzędzi, hook PreToolUse per agent, `omitClaudeMd`, brak powłoki u agentów „ślepych", schemat wyniku, `maxTurns`, prompty składane przez skrypt), nie prozа w prompcie.
- Orkiestracja w skrypcie workflow, nie w `CLAUDE.md`; hooki tylko do egzekwowania, nigdy do sterowania przepływem.
- Uwaga z code review bez `rule_ref` (kryterium akceptacji / konwencja / konstytucja / CWE) i dowodu jest opinią i nie blokuje. Arbiter tylko dla sporów (UPHOLD / OVERTURN / ESCALATE). Zaakceptowana uwaga dająca się uogólnić → kandydat na check deterministyczny.
- Po zamknięciu story `specs/{story}/` jest niemutowalną historią; żywa prawda = kod + testy + generowana mapa możliwości. Analityk biznesowy czyta tylko mapę możliwości.
- Kontrakt API = różnica względem swaggera wygenerowanego ze zbudowanego backendu; każde twierdzenie o istniejącym zachowaniu wymaga dowodu.
- Krytyk pomysłu (warstwa biznesowa) dostaje propozycję + raport możliwości + listę odrzuconych opcji, ale nie rozmowę; jego raport trafia do właściciela niefiltrowany; jedna runda + jedna replika.
- Sekcja o starej flocie ma zniknąć z `CLAUDE.md` (subagenci dziedziczą go domyślnie).
- **Identyfikator story (2026-09-24, z prototypu SpecKita):** `<story>` = numer SpecKita `NNN`; gałąź `NNN-slug`, katalogi `specs/NNN-slug/` i `runs/NNN-slug/`. Skrypty SpecKita rozpoznają feature po nazwie gałęzi i dla gałęzi spoza wzorca po cichu wskazują cudzy katalog — skrypt `status` i dyrygent odmawiają pracy na gałęzi niepasującej do wzorca.
- **Izolacja agenta ślepego (z prototypów):** `omitClaudeMd: true` + allowlista narzędzi bez Agent/Skill/powłoki + hook ACL (allowlist katalogów, fail-closed). Znany kanał, którego nie da się zamknąć: sekcja `gitStatus` wstrzykiwana każdemu subagentowi ujawnia NAZWY niezacommitowanych/przemianowanych plików. `tools: []` oznacza wszystkie narzędzia.
