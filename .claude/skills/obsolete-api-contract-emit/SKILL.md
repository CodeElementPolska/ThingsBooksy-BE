## User Input

```text
$ARGUMENTS
```

You **MUST** consider the user input before proceeding (if not empty).

The only supported argument is the optional `--force` flag. Any other value is treated as ignored noise.

## Purpose

Produce a first-draft API contract that captures the FE↔BE surface implied by the freshly generated `plan.md`. The draft is later finalized (and complemented by a static `swagger.json`) by the `contract-definer` agent in Etap 4 of the agent-fleet redesign.

This skill is the canonical writer of `specs/{feature}/api-contract.md` while its status is `DRAFT`. Once the file reaches `Status: FINALIZED` the skill refuses to overwrite it unless `--force` is provided.

## Pre-Execution Checks

**Determine active feature**:
- Run `.specify/scripts/powershell/setup-plan.ps1 -Json` from repo root and parse the JSON output for `FEATURE_SPEC`, `IMPL_PLAN`, `SPECS_DIR`, `BRANCH`.
- If the script fails or `BRANCH` does not look like a feature branch (no `NNN-` prefix), abort with a clear error message.

**Verify plan exists**:
- Confirm `IMPL_PLAN` (`specs/{feature}/plan.md`) exists. If it does not, abort with: `ERROR: plan.md missing — run /speckit-plan first`.

**Idempotency gate**:
- Target path: `{SPECS_DIR}/api-contract.md` (project-relative: `specs/{feature}/api-contract.md`).
- If the target does not exist → proceed to **Outline**.
- If the target exists, read the top-of-file frontmatter and find the `Status:` field:
  - `Status: DRAFT` → overwrite freely; continue to **Outline** and report `Mode: refresh-draft`.
  - `Status: FINALIZED` and `--force` **not** passed → abort with:
    ```
    ERROR: api-contract.md is FINALIZED. Refusing to overwrite.
    Pass --force to override (manual edits only — automatic hooks must NEVER use --force).
    ```
  - `Status: FINALIZED` and `--force` passed → overwrite and report `Mode: force-overwrite-finalized`. Warn the user that downstream agents (`contract-definer`, `contract-drift-check`) may need to re-run.
  - Any other `Status` value (missing, malformed) → abort with: `ERROR: api-contract.md has invalid Status field. Inspect manually.`

**Automatic hook constraint**:
- When this skill is invoked through `extensions.yml` `after_plan` hook, `--force` is **never** passed. The hook is fail-safe by construction.

## Outline

1. **Setup**: parse the setup-plan JSON; resolve `SPECS_DIR` and `IMPL_PLAN` absolute paths.

2. **Load context**:
   - Read `IMPL_PLAN` in full.
   - Read `FEATURE_SPEC` (spec.md) in full.
   - If the feature directory contains `research.md` or `data-model.md`, read them too — they often carry the entity field lists referenced by endpoints.

3. **Derive surface**:
   - Extract every API touchpoint the plan implies. Sources, in order of trust: explicit endpoint tables, contract directories under `specs/{feature}/contracts/`, mentions in the data model, then narrative prose.
   - Classify each endpoint by HTTP method, route, owning module, request DTO, response DTO, auth requirement, and consumer (which FE component or other BE module).
   - When the plan is ambiguous, mark the field `TBD` rather than inventing — the goal is a faithful draft, not a guess.

4. **Derive scope hint**:
   - Read the `Scope:` line from the `product-strategist` handoff section if present in spec.md (`fe-only`, `be-only`, `both`).
   - If no signal is found, default to `both` and add a sentence to the Notes section stating the fallback was applied.

5. **Write `specs/{feature}/api-contract.md`** using the template in **Output template** below. Always set `Status: DRAFT`. Never set `FINALIZED` from this skill.

6. **Report**: print the target absolute path, the mode (`fresh-draft` / `refresh-draft` / `force-overwrite-finalized`), and the number of endpoints captured. End with:
   ```
   API-CONTRACT-EMIT COMPLETE
   File: specs/{feature}/api-contract.md
   Status: DRAFT
   Endpoints: {N}
   Mode: {mode}
   ```

## Output template

The file written to `specs/{feature}/api-contract.md` follows this structure:

```markdown
# API Contract — {feature-slug}

Status: DRAFT
Scope: {fe-only|be-only|both}
Plan reference: specs/{feature}/plan.md
Generated by: api-contract-emit (v1 draft)

## 1. Endpoints

| # | Method | Route | Module | Auth | Request DTO | Response DTO | Consumer |
|---|--------|-------|--------|------|-------------|--------------|----------|
| 1 | GET    | /users/me | Users | Bearer | — | `UserSummary` | `tb-user-header` |
| 2 | …      | …     | …      | …    | …           | …            | …        |

## 2. DTO shapes (draft)

### UserSummary
- `id: Guid`
- `email: string`
- `displayName: string`

### …

## 3. Cross-module dependencies

- {module-A} consumes `{IEvent}` published by {module-B}
- …

## 4. Open questions

- TBD: {field/route/auth still ambiguous in plan.md}

## 5. Notes

- {Any scope fallback applied, e.g. "No Scope signal in spec.md — defaulted to both."}
- {Mismatch found between plan.md and data-model.md, if any}
```

Sections may be empty (`_None._`) but must be present so finalization in Etap 4 has stable anchors.

## Hook integration

Register this skill in `.specify/extensions.yml` under `hooks.after_plan` as a **mandatory non-optional** entry (`enabled: true`, `optional: false`, `condition: null`). The hook runs automatically after `/speckit-plan` returns, without `--force`. Manual invocation via `/api-contract-emit --force` is reserved for the developer when intentionally redrafting a finalized contract.

## Key rules

- Use absolute paths for filesystem operations; use project-relative paths inside the emitted markdown.
- `Status: FINALIZED` is set only by `contract-definer` (Etap 4). This skill must never write `FINALIZED`.
- This skill does not emit `swagger.json` — that responsibility belongs to `contract-definer` and lands in `specs/{feature}/swagger.json` (Etap 4, decision 9).
- This skill performs no git operations and no further agent calls. It is a pure file emitter.
- Treat ambiguity as `TBD` text, not as invention. The plan-validator will challenge `TBD` density in Etap 2 item 3.
