# Recenzja projektu workflow (Opus, 2026-09-21) — zapis skrócony

Recenzent zewnętrzny (subagent Opus), bez dostępu do repo; ten sam prompt co recenzja Fable. Zapisane 2026-09-28 z kontekstu sesji projektowej.

## Werdykt
Pomysł właściciela to schemat organizacyjny przepisany na agentów, nie architektura przepływu informacji. Krytyka asystenta ~80 % słuszna, ale **zła diagnoza przyczyny**: wady audytu (1, 2, 5, 6) to brak **źródła prawdy poza LLM-em**, nie topologia komunikacji — ładniejsza topologia LLM-ów sprawdzających LLM-y odtworzy je. Trzy filary (izolacja testera, „writer musi zgłosić decyzję", arbiter) są w promptach, więc zawiodą jak poprzednio — chyba że oprze się je na prymitywach platformy (hooki per agent, `omitClaudeMd`, `maxTurns`, schemat wyjścia, worktree, skrypt Workflow z journalem). Przeoczony fakt: **subagent nie może rozmawiać z człowiekiem** — stąd fałszywe PAUSED w starej flocie.

## Najpoważniejsze zastrzeżenia
- **Z1 brak wykonywalnej definicji poprawności** → red-first proof (nowe testy muszą upaść na kodzie sprzed implementacji; przechodzące = odrzucone), kontrakt generowany nie pisany (jeden test kształtu błędu w repo; ręczny kontrakt tylko jako diff wobec swaggera z builda), traceability generowana (AC-id → `[Trait("AC","AC-3")]` → macierz skryptem; nieposkryte AC = czerwona bramka).
- **Z2 „twarde ramy" nadal promptem** → tabela reguła→mechanizm: hook PreToolUse we frontmatterze (`permissions.deny` jest globalne!), `disallowedTools`, `omitClaudeMd` (CLAUDE.md idzie do każdego subagenta), `maxTurns`, `schema` w `agent()`, brak Write u RO (raport = tekst zwracany), `isolation: worktree`, `effort`/`model`/`budget`. Hooki nie działają na wklejony tekst → prompty ślepych składa skrypt z listy ścieżek.
- **Z3 model interakcji zderza się z platformą** → twardy limit 3 bramek na story (G1 story, G2 paczka decyzji, G3 eskalacje+commit) + wyjątkowa migracja destrukcyjna; reszta = kolejka decyzji z `default`, `impact`, `decided_by: human|agent-default`; milczenie = default; `decided_by: human` wypełnia skrypt.
- **Z4 za dużo przepisań LLM→LLM** → każdy artefakt pisany raz przez jednego autora albo generowany; analityk pisze `spec.md` sam (odpada `/speckit-specify`); `swagger.json` i klient TS generowane; każde zdanie o istniejącym zachowaniu z cytatem (plik:linia), inaczej BLOCKER.
- **Z5 agenci mogą rozmawiać (`SendMessage`)** → hybryda: artefakty przez pliki ze schematem i provenance, negocjacje bezpośrednie tylko wybranym parom z `maxTurns`; ślepi nigdy nie dostają `SendMessage`.
- **Z6 aktualizacja spec = złe źródło prawdy** → `specs/{story}` niemutowalny zapis z datą; prawda żyjąca = kod, testy, generowana `capability-map`, ADR; „delta record" zamiast retro-edycji.
- **Z7 brak budżetu i pomiaru** → rejestr przebiegów z `journal.jsonl`; 5 liczb na story: przerwania, rundy do zielonego, defekty po zamknięciu (jedyna metryka jakości), odsetek uwag zamienionych w check deterministyczny, tokeny+czas.
- **Z8 bezpieczeństwo uprawnień** → deny `git push/commit`, `gh pr merge`, `ef database update` na prod; zapis do GitHuba tylko skryptem z dry-runem; treści z issues/WWW to dane, nie instrukcje (prompt injection).

## Niezgody (wybór)
- (1) prawdziwy powód: `AskUserQuestion` usuwane subagentom; sesja główna jako persona i orchestrator po 20 rundach jest stronnicza i kompakcja gubi decyzje → zrzut do pliku po każdej rundzie, budowa z czystej sesji.
- (3) `/speckit-specify` dubluje analityka i jest tym przepisaniem, które dało wadę 5; `clarify`/`analyze` redundantne.
- (5) analityk biznesowy nie czyta kodu, tylko `capability-map`.
- (6) hejter bez listy odrzuconych alternatyw zapętla te same zarzuty; dwa krytyki o rozłącznych rubrykach: scope/wartość i premortem (dane, migracje, authz, ops).
- (7) **najpoważniejsza**: kategoria (b) to dokładnie audyt 2 → zakodowana lista powierzchni wysokiego ryzyka (statusy, authz, kształt błędu, kasowanie danych, migracje destrukcyjne, PII, pieniądze, nowe UI) automatycznie = (c); DoD grepuje założenia.
- (8) weryfikacja kontraktu wobec **skompilowanego** backendu (swagger z builda) przed FE, nie wobec uruchomionej aplikacji na końcu.
- (9) izolacja testera podnosi odsetek błędnych testów → implementer widzi tylko wynik i komunikat asercji + arbitraż spec-vs-test.
- (10) arbiter wąsko (spory uwaga vs spec/konstytucja); **każda zaakceptowana uogólnialna uwaga → kandydat na check deterministyczny** (analizator Roslyn, test architektury, ESLint) — flota z każdą story tanieje.
- (12) hooki egzekwują, nigdy nie sterują przepływem (fałszywe SubagentStop/Stop z audytu wzięły się z hooków jako orkiestracji).
- (13) DoD = skrypt zbierający dowody, nie checklista odhaczana przez model.
- (14) trzy tory (hotfix / bez UI i kontraktu / pełny), tor wybiera skrypt po blast radius.
- (15) handoff + budżet anty-scope-creep + deklaracja dotkniętych modułów (blokada równoległych przebiegów).

## Niezauważone luki (15)
CLAUDE.md w każdym subagencie; workflow nie pyta człowieka (liczba uruchomień = bramki + 1); kompakcja kontekstu w długim intake; `memory:` = wyciek między story; regresje między stories; migracje EF (nieodwracalne → własna bramka, zakaz `database update` poza lokalnym); wspólna baza testowa przy równoległości; konflikty plików + Husky przy BE∥FE; zależności między stories (`BLOCKED_BY`); idempotencja i awaria w połowie (wznawianie po runId, atomowe artefakty, plik stanu); zielone bezwartościowe testy (red-first); zmiana konwencji w czasie (stosować do zmienionych linii); prompt injection z GitHub/WWW; brak definicji porzucenia story; obserwowalność.

## Pokrycie wad audytu — co dodać
1 → hook per agent, prompt ze skryptu, red-first, hash testów, zakaz notatek writera w schemacie wejścia. 2 → lista wysokiego ryzyka, `decided_by` tylko skryptem, DoD odrzuca. 3 → spec zamrożony, prawda w kodzie/testach/mapie, statusy skryptem. 4 → nazwać przyczynę (interaktywny subagent niemożliwy), hooki tylko egzekwują. 5 → kontrakt jako diff wobec swaggera z kompilacji, cytaty, jeden test kształtu błędu, FE tylko z generowanego klienta. 6 → AC-id + tagi + macierz generowana.
